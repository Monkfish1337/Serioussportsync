Four discovery pipelines, one card, four collapsible blocks

Reported as "the Sport-Video pipeline has no disable toggle". It always had
one, but only on its own page, so the Server page carried enable toggles for
the companion, Prowlarr and Bitmagnet and silently omitted the fourth source.
From the only screen where a user compares sources, Sport-Video looked like the
one that could not be switched off.

Sport-Video now sits with the other three, and what runs the pipeline came with
it: the switch, the scan schedule, the per-scan limits, the sports to scan.
What it does with a matched release -- team filters, auto-warm, per-release
TorBox actions -- stays on its own page, because those are drawn from the
promotion list rather than being properties of the pipeline.

That needed a setter that patches rather than replaces. setSportVideo rejects a
submission with no categories, correctly, and replaces the whole object, so a
save from the Server card would have blanked the fields that card never showed.
updateSportVideo merges a patch over what is stored and validates the result.
The switch keeps a setter of its own that validates nothing, because "turn this
off" must not depend on the validity of some other field -- or on a field
inside a collapsed block.

Each pipeline is a <details> block. Flat, with a switch, credentials and an
explanation each, this had become the longest card on the page and the question
an operator usually comes here to answer -- which sources are on -- was buried
in the middle of it. Each summary carries the name and the state. A pipeline
that is enabled but has no URL reads as off, because it is, and opens by
default since that is the case someone is most likely here to fix.

The two metadata API keys moved to the bottom under a heading that says what
they are: they fetch fixtures, not releases, and sitting them among the
discovery sources implied they were one.
