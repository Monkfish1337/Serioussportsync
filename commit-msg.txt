Send the rutracker query, don't just generate it

Reported bluntly and correctly: rutracker results still are not captured. The
previous commit's claim that both catalogues were "reachable inside the first
six queries" was the wrong measurement.

Six is not the number that matters. Prowlarr -- the only configured source
that reaches rutracker -- is given six queries and completes about TWO before
its deadline, so index 0 and 1 are in practice everything it asks. With the
date formats grouped by type, both of those were dotted ISO and the DMY form
sat at index 4. Bitmagnet sends all sixty, found the content, and the row was
labelled Bitmagnet; Prowlarr was never handed the one query that can match a
rutracker title. The query was generated and then never sent.

The four date tokens now alternate format instead of grouping, and every
prefix-free form goes out before any prefixed one -- a prefixed date is
measurably weaker than the bare one ("NFL 2026.08.28 Cardinals Packers" -> 0,
"Cardinals Packers 2026.08.28" -> 1), so it must not displace a format that
has not been tried at all. For Texans at Panthers:

  0  Panthers Texans 2026.08.29     dotted ISO, stored day
  1  Panthers Texans 28.08.2026     DMY, day before   -> rutracker
  2  Panthers Texans 2026.08.28     dotted ISO        -> the usenet release
  3  Panthers Texans 29.08.2026     DMY, stored day

The test pins index <= 1 now rather than < 6. The margin that looked
comfortable was the entire bug.
