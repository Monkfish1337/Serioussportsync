Make the Promotions table fit, and stop previews outrunning their deadline

Three reported faults, each measured rather than guessed at.

Promotions table cut off. The previous fix made the table scroll; it did
not make it fit. Measured in a headless browser at a 1440px viewport: the
table wanted 1386px inside a 1018px card, of which the action buttons were
690px on one `text-nowrap` line. It did scroll — but the scrollbar sits
beneath a 34-row table where nobody finds it, so Refresh and Edit simply
read as chopped off. Cut the columns down instead. Poster and Catalogs were
one short value each and neither can answer "is this promotion working";
both moved onto the name cell's secondary line. The action buttons wrap in
a 250px column. Six columns, 1018px of content in a 1018px card, nothing
overflowing. The responsive scroller stays as the narrow-viewport fallback.

Source preview timing out at 60s. WWE has no known-card list, so the named
lookups gated in the previous commit could not have been the cause. The
per-round season walk is: one request per round, config.tsdb.requestDelayMs
(3000ms) apart, continuing until five rounds in a row come back empty. For
a league running weekly TV that is forty-odd requests — over two minutes on
its own. A preview now takes the list endpoints only and carries a 45s
budget, so a slow source degrades to a partial answer instead of an error.

AEW still showing nothing upcoming. The named-lookup gate was wrong in the
one case the feature exists for. It skipped the lookups whenever any future
event came back, and AEW's list endpoints DO reach the future — they return
the next Dynamite or Collision, because AEW runs weekly TV — while All Out
never appears in them at all. One future taping satisfied the gate and the
PPVs stayed missing. The gate now asks which known cards are absent by name
and looks up only those, so the steady state costs nothing and a missing
card is actually fetched.

436 tests passing.
